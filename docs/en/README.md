# AccessCore License SDK

The license format and the judgement over it, owned by one core.

A Rust core signs tokens, verifies them, and decides what a deployment may do. Products written
in Java, Python, Go, and Rust take that decision through a thin binding. The core touches no
file, no clock, and no socket — the host supplies the values and the core returns a conclusion.
Because the issuing side and the verifying side run the same core, a release cannot ship where
one writes a format the other refuses to read.

## Layout

```
core/                       Rust workspace
├── aclic-model/            the payload format, schema number, channel, product key, release ranking
├── aclic-sign/             signing and verification, key material
├── aclic-verify/           the judgement — the order of the checks, and the statuses
├── aclic-fingerprint/      machine identifiers: reading them, and matching them
├── aclic-protocol/         activation and heartbeat bodies, and reading the answers
└── aclic-ffi/              the C ABI cdylib — the one native boundary
bindings/
├── java/                   JNA wrapper · the neutral gate · adapters
├── python/                 cffi wrapper · the neutral gate · adapters
├── go/                     cgo wrapper · the neutral gate · adapters
└── rust/                   the core directly · the neutral gate · adapters
conformance/                the vectors every binding answers the same way
include/aclic.h             the C header, generated by cbindgen
docs/en, docs/ko            every document, one folder per language
```

`aclic` shortens AccessCore License. The POSIX ACL library that ships on most Linux systems owns
the `acl_` prefix, so this one does not use it.

## Where a consumer gets it

| Language | Coordinate | How the core travels |
| --- | --- | --- |
| Java | `dev.accesscore:license-sdk` | inside the jar, extracted at run time |
| Python | `accesscore-license` | inside the wheel |
| Go | `github.com/accesscore-dev/accesscore-license-sdk-dist/go` | linked statically |
| Rust | `aclic` | linked statically |

This repository is private and holds the core. A release publishes to the registries above and
pushes a consumer-facing tree to the public repository — Go is why that exists, since `go get`
resolves a module by fetching its source. See [repositories.md](repositories.md).

## Building

```
cargo test --workspace                        the core
./scripts/build-native.sh --host-only         the library this machine needs
cd bindings/java   && ./gradlew test          the Java binding, and its conformance run
cd bindings/python && python -m pytest tests  the Python binding
cd bindings/go     && go test ./...           the Go binding
cargo build -p aclic-ffi --features header    regenerate include/aclic.h
```

A release builds every platform with `./scripts/build-native.sh`, which needs the cross
toolchains. A platform whose toolchain is missing is reported and skipped locally, and fails the
release build in CI.

## Reading it

Start with [concepts.md](concepts.md) — what the core owns, what the host owns,
